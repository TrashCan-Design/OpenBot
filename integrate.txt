1. EXECUTIVE SUMMARY & ARCHITECTURAL INVARIANTS
--------------------------------------------------------------------------------
OpenBot Dual-Engine splits browser automation across two complementary local
execution tiers without modifying or weakening existing security boundaries:

- Tier A (Autonomous Headless - Obscura Engine, CDP :9222):
  Lightweight statically linked Rust headless engine for high-throughput,
  low-latency DOM navigation, extraction, and batched macro execution.
  Runs locally (packaged binary) or inside the Linux container/VPS.

- Tier B (Visual / Interactive - Qutebrowser on X11 DISPLAY :1, CDP :9223):
  Keyboard- and IPC-driven QtWebEngine GUI browser running inside the hardened
  trycua/xfce-cua container/VPS on DISPLAY :1, bridged via an authenticated
  Unix socket (/run/user/1000/openbot-qute-bridge.sock) and noVNC/SSE takeover.

Mandatory Invariants (Verified on release/0.1.144):
1. Target release/0.1.144 ONLY; keep codex/windows-installer untouched.
2. Strictly honor banned-list rules: zero Boat VMs, zero cloud relay
   (serve --relay), zero guest meeting bots, zero vendor hosting/billing.
3. Strict openbot / OPENBOT_ / com.openbot.* primary branding for all new
   identifiers, environment variables, labels, and sockets. Keep OMB_* /
   com.openmausbot.* strictly as backward-compatible read fallbacks where
   existing contracts require them.
4. Preserve BATCH_RUNNERS in server/computer-tool-list.ts:17,25-27
   (run_steps and run_script remain blocked on the CUA computer MCP server).
   Batching is ONLY added as schema-validated browser_batch on the browser
   MCP server.
5. Keep zero published CDP ports on containers/VPS (preserve
   dockerPortsAreLocal() in server/container-computer.ts:667-692 and
   hasNoPublishedPorts() in server/vps-computer.ts:459-473) by tunneling CDP
   and MCP over `docker exec -i` + `socat`.


2. CRITICAL CORRECTIONS & GAPS IDENTIFIED IN fast.txt
--------------------------------------------------------------------------------
Codebase inspection on release/0.1.144 uncovered the following discrepancies in
fast.txt that MUST be handled as documented below during implementation:

1. fast.txt §4.4 ("browser_batch & run_steps") vs. BATCH_RUNNERS Invariant:
   - fast.txt line 28 mentions `run_steps`.
   - server/computer-tool-list.ts:17,25-27 intentionally blocks `run_steps` and
     `run_script` (`BATCH_RUNNERS`) on CUA computer tools.
   - Correction: Reject `run_steps` for CUA completely; implement ONLY
     schema-validated `browser_batch` on the `browser` MCP server (without
     any `eval` step), and leave server/computer-tool-list.ts untouched.

2. BrowserRuntime vs. ChromeEngine (`BrowserService`) Dispatch Split:
   - server/browser/tools.ts and server/browser/dispatch.ts serve ONLY
     ChromeEngine (server/browser/service.ts:30,394).
   - BrowserRuntime (server/browser-runtime.ts:577-581,989-994) fetches
     tools/list from the child MCP process and appends `withOmbTools(...)`.
   - Correction: Unless `obscura mcp` natively exposes `browser_batch`,
     register `BROWSER_BATCH_TOOL_SPEC` in BOTH `server/browser/tools.ts` AND
     `BrowserRuntime` (`withOmbTools` / `agentRequest`), enforcing `BrowserLanes`,
     `gate.owner === null`, `deadline`, `SecretHolds`, and `scrubBrowserResult`.

3. `browser_batch` `fill` Step Schema Field Name:
   - fast.txt:208-209 uses `"value"` in `fill`.
   - server/browser/tools.ts:59 (`agent_browser_fill`) uses `"text"`.
   - Correction: Use `"text"` for `browser_batch`'s `fill` step to stay
     consistent with `agent_browser_fill`.

4. `ensureManagedBrowserConfig` & Egress Purpose:
   - fast.txt:199 claims `managedBrowserConfigPath` blocks local files/networks.
   - Actual server/browser-engine.ts:66-75 writes `{}\n` so user `~/.agent-browser`
     configs cannot leak shared profiles; egress blocking is enforced by
     `browserEgress` (`server/browser/egress/gate.ts`) via `AGENT_BROWSER_PROXY`.

5. QtWebEngine `--no-sandbox` Requirement Inside Hardened Containers:

     containers with `--cap-drop ALL --cap-add SETUID --cap-add SETGID` and
     seccomp blocking unprivileged user namespaces.
