1. EXECUTIVE ARCHITECTURE OVERVIEW & END-TO-END TOPOLOGY
--------------------------------------------------------------------------------
The OpenBot Dual-Engine system splits browser execution into two complementary tiers:

- Tier A (Autonomous Headless - Obscura Engine):
  Runs either locally on the Windows desktop or inside the Linux container/VPS.
  Written in Rust, exposing native CDP on port :9222 and MCP stdio interfaces.
  Cold-starts in <50ms, consumes <50MB RAM (compared to ~500MB - 2.8GB for Chromium).
  Handles all automated web scraping, data extraction, form submission, and navigation
  by directly executing atomic, batched DOM and accessibility tree operations without
  visual screenshot round-trips.

- Tier B (Visual GUI & Interactive Takeover - Qutebrowser Engine):
  Runs on X11 DISPLAY :1 inside the Linux remote desktop (trycua/xfce-cua container).
  Lightweight keyboard/IPC-driven QtWebEngine GUI browser.
  Exposes an instant Unix domain command socket (/tmp/qutebrowser-ipc) and CDP port :9223.
  Rendered directly into the container's virtual display and streamed via noVNC (port 6901)
  to the Windows Electron Desktop and Android Mobile Chrome Custom Tabs.
  Used when human verification, CAPTCHAs, 2FA challenges, visual validation, or live
  user driving is required.

2. WHY OBSCURA + QUTEBROWSER SOLVES OPENBOT'S 8-MINUTE BOTTLENECK
--------------------------------------------------------------------------------
2.1 Root Cause Analysis of the Bottleneck:
OpenBot's legacy remote computer control architecture relies on sequential multimodal
vision loops via heavy CUA drivers:
1. Every individual UI action (navigation, click, type, scroll) captures an uncompressed
   full-desktop PNG (~3.2 MB).
2. The image is compressed or transferred over WAN/SSH to the multimodal LLM for visual
   reasoning, OCR, and coordinate extraction.
3. The server sends mouse coordinates (`click(x, y)`) back to the CUA driver on the
   remote desktop, waiting for display updates.
4. Over a typical 15–25 step automation workflow, this round-trip latency compounds to
   over 500 seconds (8.3 minutes), consuming excessive WAN bandwidth and driving container
   RAM consumption to 500MB - 2.8GB (as documented in upstream commit 1c3d3fe01).

2.2 The Dual-Engine Resolution:
1. Direct DOM/Accessibility Execution (Obscura):
   Obscura bypasses visual screenshot capture and coordinate guessing entirely. DOM
   manipulation, selector clicking, and data extraction execute via batched CDP/MCP
   primitives in <50ms per step. A 20-step macro completes in <3 seconds instead of 8 minutes.
2. Keyboard-Hinted Navigation (Qutebrowser):
   When visual GUI is strictly required (or during user takeover), Qutebrowser provides
   instant keyboard hints (:open, f [hint], gi) dispatched via IPC in 10ms without mouse
   dragging or coordinate calculations.
3. Cold-Start Reduction:
   Obscura boots in 45ms (30x faster than Chrome headless-shell).
4. RAM & Resource Relief:
   Obscura consumes <50MB RAM compared to Chrome's 500MB+, preventing Linux container OOM
   kills and memory thrashing.

4. SUBSYSTEM 2: DUAL-BROWSER ROUTING ENGINE IN OPENBOT SERVER
--------------------------------------------------------------------------------
4.1 Intent & Surface Router
- Located in server/browser/engines.ts and server/browser-engine.ts:
  - Default Route: Obscura Engine (autonomous headless mode). All web scraping, DOM queries,
    and background tool calls route here.
  - Interactive Route (Qutebrowser): Triggered dynamically when:
    a) Prompt explicitly requests visual desktop ("see screen", "show browser", "GUI").
    b) Obscura encounters an interactive challenge (Cloudflare Turnstile, reCAPTCHA, 2FA).
    c) Person initiates live takeover via Desktop UI or Mobile Companion.
- State Synchronization:
  - Runtime cookie and session transfer via CDP Storage.getCookies and Storage.setCookies
    over localhost between port 9222 and 9223, avoiding SQLite locking issues.

4.2 Environment & Flag Sanitizer (server/browser-engine.ts)
- Sanitizes environment variables: Replaces OMB_* with OPENBOT_* while maintaining fallback.
- Strips --no-sandbox when running outside containerized environments.
- Injects OPENBOT_BROWSER_CDP_ENDPOINT=http://127.0.0.1:9222.

4.3 Managed Config Generation
- managedBrowserConfigPath: Replaces omb-managed-config.json with openbot-managed-config.json.
- Restricts local file access and blocks unauthorized private network traversals.

4.4 Batched Macro Execution (server/browser-runtime.ts)
- Introduces `browser_batch` tool:
  Allows the agent to emit atomic multi-step execution graphs:
  {
    "steps": [
      { "action": "navigate", "url": "https://service.internal/login" },
      { "action": "wait_for", "selector": "#username" },
      { "action": "fill", "selector": "#username", "value": "agent" },
      { "action": "fill", "selector": "#password", "value": "••••••" },
      { "action": "click", "selector": "button[type=submit]" },
      { "action": "extract", "selector": ".dashboard-summary" }
    ]
  }
  Obscura executes this entire pipeline in a single <200ms batch, eliminating WAN round-trips.


5. SUBSYSTEM 3: WINDOWS DESKTOP APP & INSTALLER INTEGRATION
--------------------------------------------------------------------------------
5.1 Bundling Obscura for Windows in scripts/build-windows-browser-vendor.mjs
- Compilation Toolchain:
  Target: x86_64-pc-windows-gnu cross-compiled on Linux x64 runner using x86_64-w64-mingw32-gcc.
- Static Runtime Linking Invariant (Prevents Clean-Machine Crash 0xc0000135):
  Must pass explicit static CRT and MinGW flags in RUSTFLAGS:
    RUSTFLAGS="-C target-feature=+crt-static -C link-args=-static -C link-args=-static-libgcc"
  Ensures no dynamic dependency on libwinpthread-1.dll or libgcc_s_seh-1.dll.
- Windows Stdio Handle Safety:
  Patch third_party/browser/agent-browser-windows-stdio.patch must clear HANDLE_FLAG_INHERIT
  on stdio handles (stdin, stdout, stderr) and filter INVALID_HANDLE_VALUE (-1) to prevent
  broken pipe EOF hangs. Spawns detached daemon with CREATE_NO_WINDOW (0x08000000) and Stdio::null().
- Output & Provenance:
  Produces dist-native/browser/win32-x64/obscura.exe and records SHA-256 in provenance.json.
  Sanitizes temporary scratch directories from omb-browser-vendor- to openbot-browser-vendor-.

5.3 Windows-to-Linux Remote Desktop Tunneling
- Overcoming Windows OpenSSH Limitations:
  Windows OpenSSH lacks Unix domain socket ControlMaster multiplexing (as noted in
  server/vps-ssh.ts:72).
  OpenBot manages persistent child SSH tunnels via server/vps-computer.ts.
- Forwarded Port Topology:
  ssh -N \
      -L 127.0.0.1:<local_vnc_port>:127.0.0.1:6901 \
      -L 127.0.0.1:<local_obscura_port>:127.0.0.1:9222 \
      -L 127.0.0.1:<local_qute_port>:127.0.0.1:9223 \
      user@vps
  Strict 127.0.0.1 loopback binding prevents IPv6 (::1) aliasing dropouts on Windows.

- Adds dual-engine validation suite:

  4. Multi-bot isolation: Validates Bot A and Bot B run concurrently with isolated profiles.

- In android/app/src/main/kotlin/com/openmausbot/companion/browser/CloudDesktopBrowser.kt:
  Uses Android Jetpack CustomTabsIntent to launch Chrome Custom Tabs.
- Architecture Rationale (Why Custom Tabs > WebView):
  1. Sandboxed process: Heavy WebRTC/WebSocket decoding cannot cause OOM crashes in companion.
  2. Full hardware canvas acceleration and WebAssembly for silky-smooth noVNC rendering.
  3. Visible trusted origin bar prevents session spoofing and credential phishing.
  4. URL is minted per join, handed directly to browser, and never retained in app memory.

6.4 Low-Bandwidth Mobile Preview Pipeline (1280x720 JPEG SCREENSHOT_TRANSFER)
- In server/vps-computer.ts:56–62 and container-computer.ts:
  Downscales full-res screenshots using Pillow:
    from PIL import Image
    with Image.open(input_path) as image:
        image.thumbnail((1280, 720))
        output = io.BytesIO()
        image.convert("RGB").save(output, format="JPEG", quality=70)
  Reduces payload from 3.5MB PNG to ~50KB JPEG (98% reduction).
  Feeds GET /api/bots/:id/browser/live SSE stream at 1–2 fps for live autonomous monitoring.

6.5 Mobile Touch-Takeover & Gesture Mapping
- BrowserTouchSurface.kt & RemoteGestures.kt:
  Feeds touch events into GestureCore, mapping coordinates into GestureIntent:
  - Tap -> Left Click / Press
  - Long-press -> Right Click
  - Two-finger pan -> Scroll
  - Pinch -> Local zoom (does not reflow remote page)
- When user switches from Autonomous (Obscura) to Interactive Takeover (Qutebrowser):
  Obscura flushes cookies -> Qutebrowser opens target page on DISPLAY=:1 -> User takes over.

7.1 Patch: scripts/build-windows-browser-vendor.mjs (Static MinGW Linking & Handle Safety)
```javascript
export const WINDOWS_VENDOR_TARGET = "x86_64-pc-windows-gnu";
export const OBSCURA_VENDOR_VERSION = "0.2.6";

function command(file, args, cwd, { input, capture = false } = {}) {
  const result = spawnSync(file, args, {
    cwd, input, encoding: "utf8", timeout: 30 * 60_000,
    stdio: capture || input !== undefined ? ["pipe", "pipe", "pipe"] : "inherit",
    env: {
      ...process.env,
      // Enforce static CRT and static MinGW runtime to prevent 0xc0000135 crash on clean Windows
      RUSTFLAGS: "-C target-feature=+crt-static -C link-args=-static -C link-args=-static-libgcc",
      CARGO_TARGET_X86_64_PC_WINDOWS_GNU_LINKER: "x86_64-w64-mingw32-gcc",
    },
  });
  if (result.error || result.status !== 0) {
    throw new Error(`${file} ${args.join(" ")} failed: ${result.error?.message ?? result.stderr ?? result.status}`);
  }
  return result.stdout?.trim() ?? "";
}
```

7.2 Patch: third_party/browser/agent-browser-windows-stdio.patch (Complete Handle Coverage)
```rust
#[cfg(windows)]
pub(crate) fn prevent_stdio_handle_inheritance() {
    use std::os::windows::io::AsRawHandle;
    use windows_sys::Win32::Foundation::{SetHandleInformation, HANDLE_FLAG_INHERIT, INVALID_HANDLE_VALUE};

    unsafe {
        for handle in [
            std::io::stdin().as_raw_handle(),
            std::io::stdout().as_raw_handle(),
            std::io::stderr().as_raw_handle(),
        ] {
            if !handle.is_null() && (handle as isize) != INVALID_HANDLE_VALUE {
                let _ = SetHandleInformation(handle as isize, HANDLE_FLAG_INHERIT, 0);
            }
        }
    }
}
```

7.5 Patch: Fast IPC Bridge Daemon (cua-qutebrowser-bridge.py)
```python
#!/usr/bin/env python3
"""OpenBot Qutebrowser IPC Bridge Daemon for DISPLAY=:1."""
import asyncio
import json
import os
import sys

IPC_SOCKET = os.environ.get("QUTE_IPC_SOCKET", "/tmp/qutebrowser-ipc")

async def send_qute_command(command: str) -> str:
    reader, writer = await asyncio.open_unix_connection(IPC_SOCKET)
    payload = json.dumps({"args": command.split(), "target_arg": None}) + "\n"
    writer.write(payload.encode("utf-8"))
    await writer.drain()
    response = await reader.readline()
    writer.close()
    await writer.wait_closed()
    return response.decode("utf-8")

async def handle_client(reader, writer):
    data = await reader.read(4096)
    req = json.loads(data.decode("utf-8"))
    action = req.get("action")
    if action == "open":
        res = await send_qute_command(f":open {req['url']}")
    elif action == "click":
        res = await send_qute_command(":hint")
    elif action == "type":
        res = await send_qute_command(f":insert {req['text']}")
    elif action == "scroll":
        res = await send_qute_command(f":scroll-page 0 {req.get('dy', 1)}")
    else:
        res = json.dumps({"error": f"Unknown action: {action}"})
    writer.write(res.encode("utf-8"))
    await writer.drain()
    writer.close()

async def main():
    bridge_socket = "/run/user/1000/openbot-qute-bridge.sock"
    if os.path.exists(bridge_socket):
        os.remove(bridge_socket)
    server = await asyncio.start_unix_server(handle_client, bridge_socket)
    async with server:
        await server.serve_forever()

if __name__ == "__main__":
    asyncio.run(main())
```

9. DUAL-ENGINE IMPLEMENTATION SPECIFICATION & DEFERRED EXECUTION PLAN
--------------------------------------------------------------------------------
Status: SPECIFICATION ONLY (Production implementation deferred per user directive).
Target Branch: release/0.1.144 (or designated integration branch)

9.1 Dual-Engine Architecture & Separation of Concerns
------------------------------------------------------
1. Obscura Engine (Autonomous Headless Tier):
   - Scope: High-throughput, low-latency, DOM-level automation, scraping, and background task execution without visual GUI overhead.
   - Packaging: Statically linked Rust binary (obscura / obscura.exe) providing CDP endpoint (default port 9222) and MCP stdio interface.
   - Resource Ceiling: Target RSS footprint < 60 MB, cold-start < 50 ms.
   - Security Invariant: Isolated execution sandbox; PATH sanitization; strict OpenBot branding without vendor/cloud relay dependencies.

2. Qutebrowser Engine (Visual / Interactive Tier):
   - Scope: GUI interactive browsing, human takeover, complex authenticated sessions, and visual web rendering.
   - Environment: Runs on X11 DISPLAY :1 inside Linux container/VPS or local desktop environment; controlled via QtWebEngine CDP (port 9223) and Unix domain IPC socket bridge (/run/user/1000/openbot-qute-bridge.sock).
   - CUA Integration: Dedicated bridge (cua-qutebrowser-bridge.py) translating semantic actions (open, click, type, scroll) into native Qutebrowser commands with zero collision on CUA driver input streams.

9.2 Dual-Browser Routing Logic (server/browser-engine.ts & server/browser-runtime.ts)
-------------------------------------------------------------------------------------
- Routing Policy:
  * Default routing target for headless tool calls and scraping: Obscura engine.
  * Interactive takeovers, visual inspection, or explicit surface: "gui" requests: Qutebrowser (or Chromium desktop).
- Batched Execution (browser_batch):
  * Sequence multiple atomic actions (goto, evaluate, screenshot, fill, click) in a single round-trip over CDP/IPC to eliminate multi-step roundtrip network stalls.
- Reclaim and Lifecycle Guards:
  * Memory watchdog and idle-reclaim routines (watched() in browser-runtime.ts) must monitor both Obscura and Qutebrowser daemon PIDs, protecting against zombie processes and leaked IPC sockets.

9.3 Verification Gates Prior to Activation
------------------------------------------
- Gate A: Static link checks ensuring zero foreign dynamic library dependencies (MinGW / non-MSVC DLL leaks on Windows).
- Gate B: Clean cold-start, multi-frame capture, and memory eviction stress tests under bounded cgroup memory limits.
- Gate C: Strict OpenBot branding compliance (no legacy omb_ / maus_ tokens; no cloud relay or vendor hosting dependencies).
